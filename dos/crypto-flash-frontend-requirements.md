# Crypto Flash APP 前端开发需求说明(给 AI 开发助手)

## 0. 如何使用本文档

本文档是交给 AI 开发助手的完整开发指引,请通读后再动手。所有页面的视觉基准是随文档提供的设计稿文件 code.html(高保真视觉稿 V1.0,共 9 个 APP 页面示意)。文档中凡标注"设计稿未体现"的内容,是为了让功能形成闭环而补充的,请按本文档的默认方案实现,并在代码里留出易于修改的位置。凡标注"待确认"的内容,先按默认方案做,不要自行发挥,也不要阻塞后续开发，注意不开发WEB后台页面就是APP页面

## 1. 项目定位与开发边界

产品是一款加密货币新闻快讯与交易点位 APP:用户可以看实时快讯、看交易团队发布的做多/做空点位,持有平台指定 NFT 的用户可以解锁全部点位。

我方职责只有一件事:开发 APP 前端(uni-app + Vue)。后端由另一个团队开发,我方负责与后端接口对接联调。

因为后端接口文档目前还没有到位,开发策略是"前端先行":先用 Mock 数据把全部页面、交互、各种状态完整跑通,同时搭好一层可切换的接口对接层,等后端接口就绪后,只替换对接层的实现即可,页面代码不应该再大改。

明确不做的事情:后端接口、数据库、服务器部署;设计稿第 11 项"管理后台(Web)"不在本次范围内,仅作背景参考,请完全忽略;NFT 合约与链上开发;第三方行情与链上查询服务本身(由客户提供,并且经由后端提供给前端)。

## 2. 技术与工程要求

1. 框架:uni-app + Vue 3(Composition API,script setup 写法),状态管理用 Pinia。如果客户或团队已明确使用 Vue 2,以他们的为准,这一点待确认。
2. 目标平台:以 iOS / Android 原生 APP 为主(uni-app App 端)。开发期间同时保证 H5 预览可以运行,方便快速对照设计稿走查。
3. 样式:使用统一的设计 Token(颜色、圆角、字号、间距)集中定义,页面里不要散落硬编码色值。要支持浅色主题(默认)和深色主题(见 4.4 节)。
4. 适配:必须适配刘海屏和底部安全区;使用 rpx 或等比方案,基准按 750rpx 宽;文字和间距要适配常见 Android 与 iOS 屏幕。
5. 国际化:所有界面文案走语言包,默认中文,并搭好中文/英文切换框架(登录页右上角有"中 / EN"切换)。首期以中文完整为准,英文文案可按同结构补齐,是否需要完整英文待确认。
6. 目录建议:pages(页面)、components(通用组件)、api(接口层,按模块分文件)、mock(模拟数据,与 api 同签名)、store(Pinia)、utils(请求封装、格式化、时间、价格)、locales(语言包)、styles(Token 与主题)。
7. 通用组件必须抽出复用,至少包括:底部 TabBar、胶囊筛选栏、快讯条目、点位卡片、币种图标、方向标签(做多/做空)、状态标签、情绪标签(利好/利空/中性)、开关行、菜单行、空状态、加载态骨架或占位、错误重试、通用弹窗、Toast。
8. 不要引入未经说明的大型第三方库;需要引入时说明理由,优先使用 uni-app 生态成熟插件。

## 3. 设计规范(从 code.html 提取)

重要提醒:设计稿里的手机是缩小后的示意框(可用宽度约 271px,字号只有 8 到 11px),千万不要照搬 px 数值。请以 375 逻辑宽度的手机为基准整体放大约 1.4 倍来还原,保证正文不小于 12px,最小辅助文字不小于 10px。还原的是比例、层级、颜色和布局,而不是像素。

颜色:
- 品牌主色蓝 #2563EB,按下态 #1D4ED8,浅蓝底 #EFF6FF 与 #DBEAFE。
- 上涨/做多/利好用绿色 #10B981,下跌/做空/利空/止损用红色 #EF4444。设计稿采用绿涨红跌,请按此实现,并把涨跌配色做成一个全局配置项,方便以后切换成红涨绿跌(待确认客户偏好)。
- 页面背景浅灰白 #F8FAFC,卡片白色,卡片边框 #E2E8F0。
- 主文字深色 #0F172A,次要文字 #64748B,弱提示文字 #94A3B8。
- 收藏与提示用琥珀色 #F59E0B。
- 深色主题参考底色 #0B111E 与 #0F172A。

字体:优先 Inter 与思源黑体(Noto Sans SC),系统字体兜底。价格、点位数字使用等宽数字风格,方便对齐。价格用千分位,小数位按币种精度处理(如 BTC 两位、SOL 两位)。

形态:卡片圆角约 12 到 16px;按钮圆角约 8 到 12px;筛选标签是胶囊形;选中态为蓝底白字,未选中是白底或浅灰底灰字。整体风格:专业、干净、金融终端感,信息密度较高但层次清晰。

快讯重要级别配色:紧急为红色,要闻为蓝色,普通为灰色;条目左侧有一条竖线,颜色与级别一致。

## 4. 全局规则与通用行为

### 4.1 导航结构

底部 TabBar 共 4 个:首页、快讯、点位、我的。选中项为蓝色并使用实心图标,未选中为灰色线性图标。除了这 4 个主页面外,其余页面均为二级页面,顶部为返回导航。

### 4.2 登录态

- 未登录用户进入 APP 先到登录页;登录后进入首页。是否允许未登录浏览快讯(游客模式)待确认,默认必须登录。
- token 保存在本地存储,启动时校验;接口返回未登录或 token 失效时,清除登录态并回到登录页,登录成功后尽量回到原页面。
- "保持信任登录(30 天)"勾选后,登录有效期按 30 天处理(具体以后端为准,前端只是传参数)。

### 4.3 通用状态(每个列表页、详情页都必须具备)

1. 加载中(首次进入)。
2. 下拉刷新与上拉加载更多;没有更多时显示"没有更多了"。
3. 空状态(带图标和文案,例如"暂无快讯")。
4. 请求失败状态(带"重试"按钮),网络断开有明确提示。
5. 弱网或重复点击时,按钮防抖并显示提交中状态。

### 4.4 主题模式

"我的"页面里有"主题模式"入口(设计稿显示为"浅色模式"),提供 浅色 / 深色 / 跟随系统 三个选项。设计稿只有浅色稿,深色主题请基于颜色 Token 自动推导,首期保证深色下可读、无明显错色即可,不追求逐页精修。

### 4.5 免责声明

设计稿多处出现固定声明"仅供参考,不构成投资建议,加密资产投资存在高风险,请 DYOR。"请在以下位置展示:点位详情底部、登录页底部(文案略有不同,以设计稿为准)、快讯详情底部(补充)。文案统一放语言包。

### 4.6 时间与数字格式

- 快讯列表使用相对时间:刚刚、3分钟前、5小时前、昨天;超过约 24 小时显示 年-月-日 时:分。详情页显示完整时间(例如 2026-07-13 20:45)。时区以后端返回或用户手机时区为准,待确认。
- 涨跌幅带正负号和百分号,例如 +2.35%、-1.28%,并按涨跌上色。

### 4.7 外链与复制

打开外部链接(NFT 购买页、Telegram、WhatsApp)使用系统浏览器或对应 APP 的深度链接;复制内容后给出"已复制"的 Toast。所有链接、账号、二维码图片都从后端接口获取,不允许在前端硬编码。

## 5. 页面需求(共 18 个页面或弹窗)

### 5.1 登录页(设计稿有)

布局从上到下:
1. 顶部左侧:一个"Mainnet"网络状态小标签,带绿色圆点;顶部右侧:"中 / EN"语言切换。
2. Logo 区:蓝紫渐变圆角方块,内含闪电图标;下面是"Crypto Flash"字样加一个"PRO"小徽标;再下面是副标题"专业级加密资讯与高胜率策略终端"。
3. 登录方式切换:两个分段标签"账号登录"和"钱包连接"。
4. 账号登录表单:"邮箱 / 用户名"输入框(右侧有邮箱图标);"动态验证码"输入框,右侧带"重发验证码"按钮,获取后倒计时显示"60s后可重发";输入正确时输入框右侧显示绿色对勾。
5. 表单下方一行:左边勾选项"保持信任登录 (30天)",右边链接"忘记密码?"(进入找回密码页)。
6. 主按钮:"进入交易终端 • 探索点位",宽度撑满,蓝色,右侧带箭头图标。
7. 分隔线加文字"快捷连接与第三方",下面是 Microsoft、Google 两个圆形图标按钮。
8. 底部协议行:勾选"同意《服务协议》与《隐私条款》",未勾选不允许登录;下面一行小字"资产与市场波动剧烈,交易前请独立研究 (DYOR)"。

交互要求:表单校验(必填、邮箱格式)、按钮 loading、验证码倒计时。"钱包连接"标签下显示钱包连接的界面:一个"连接钱包"主按钮,连接成功后走签名登录。设计稿只有账号登录这一态,钱包连接下的界面请按同样风格补充。

注意(待确认):设计稿账号登录只有"邮箱/用户名 + 动态验证码",没有密码框,但又有"忘记密码"入口。默认实现为:登录表单支持"密码"与"验证码"两种凭据形态,由一个配置项决定显示哪一种,先按设计稿显示验证码形态,并在与后端对接时最终确认。

技术提示:钱包连接在 uni-app 原生 APP 里没有浏览器注入的钱包对象,推荐走 WalletConnect 或钱包深度链接唤起,流程是"向后端取随机串 → 钱包签名 → 把地址和签名提交给后端换取登录态"。Google / Microsoft 第三方登录走系统浏览器 OAuth 或原生插件,拿到授权凭证后交给后端。这两项属于技术风险较大的部分,请先完成界面与流程占位,放到联调阶段再实现,不要阻塞主线。

### 5.2 注册页(设计稿未体现,补充)

风格与登录页一致。字段:邮箱或手机号、验证码(带倒计时)、设置密码、确认密码、同意协议勾选。提交成功后自动登录或回到登录页(待确认,默认自动登录)。需要密码强度提示和两次密码一致校验。

### 5.3 找回密码页(设计稿未体现,补充)

三步流程:输入邮箱或手机号并获取验证码 → 校验验证码 → 设置新密码。完成后提示成功并返回登录页。每一步都要有明确的错误提示。

### 5.4 修改密码页(设计稿未体现,补充)

入口在"我的 → 安全设置"。字段:原密码、新密码、确认新密码。修改成功后提示并要求重新登录。

### 5.5 2FA 绑定/验证页(设计稿未体现,补充)

入口在"我的 → 安全设置"。未绑定状态:展示后端返回的绑定二维码和密钥文本(支持复制),提示用户使用身份验证器 APP 扫描,再输入 6 位动态码完成绑定。已绑定状态:显示"已开启",允许关闭(关闭需再次输入动态码)。登录时如果账号已开启 2FA,需要增加二次验证步骤(与登录页"动态验证码"如何配合,待与后端确认)。

### 5.6 首页(设计稿有)

顶部:左侧 Logo 圆形图标加"Crypto Flash"名称;右侧铃铛图标,有未读时右上角显示蓝色小点,点击进入消息列表(见 5.19)。

搜索栏:圆角输入框,占位文字"Search news, coins, projects...",点击进入搜索结果页。

板块切换胶囊:精选、日历、数据、更多。当前选中"精选"。注意:设计稿写的是"日历",但项目方案文档写的是"日报",两者不一致,待确认。设计稿只给出"精选"板块的内容,其余三个板块先搭好切换框架和空状态占位,内容待确认后再补;"数据"板块默认可先复用多空比卡片并做扩展。

"精选"板块内容从上到下:
1. 多空比卡片(BTC):标题"多空比 (BTC)"带一个小的说明图标,点击可弹出说明;右上角"更多 >"。中间三列:左边"多方"与百分比(绿色,如 57.62%),中间是一个半圆仪表盘,内部显示比值(如 1.36),下面小字"多方主导";右边"空方"与百分比(红色,如 42.38%)。下面是一条红绿双色占比条。最底部一行显示各交易所比值,例如"OKX: 1.33"和"币安: 1.40"。占比、比值全部来自接口,方向文案根据比值自动判断(多方主导/空方主导/均衡)。
2. 热门快讯精选:3 条横向卡片,每条左侧是方形缩略图,右侧标题(单行截断)加一行小字"5 小时前 • 以太坊"(时间加分类)。点击进快讯详情。
3. 市场行情:标题"市场行情"与"更多 >";下面四宫格,依次是 BTC/USDT、ETH/USDT、SOL/USDT、BNB/USDT,每格显示交易对、最新价、24 小时涨跌幅(按涨跌上色)。价格需要实时刷新,见 7.4 节。"更多 >"进入完整行情列表,该页设计稿未体现,首期可做成简单的行情列表页或先隐藏入口,待确认。

底部为 TabBar。

### 5.7 搜索结果页(设计稿未体现,补充)

从首页搜索框或快讯列表右上角搜索图标进入。顶部搜索输入框自动聚焦;输入前显示"搜索历史"(可清空)与"热门搜索";提交后按类型分标签展示结果:综合、快讯、币种、项目。快讯结果复用快讯条目,币种结果显示币种图标、名称、最新价与涨跌幅,项目结果显示名称与简介。无结果显示空状态。

### 5.8 快讯列表页(设计稿有)

顶部是横向可滚动的分类胶囊:全部、BTC、ETH、山寨币、交易所、政策,右侧固定一个搜索图标。注意方案文档只列了前五项,设计稿多了"政策",分类应由后端接口返回,前端不写死,设计稿这几项作为默认与兜底。

列表是时间轴风格,每一条:
1. 左侧有竖线,颜色按级别(紧急红、要闻蓝、普通灰)。
2. 第一行:级别标签(紧急、要闻、普通)加相对时间。
3. 标题:粗体,最多两行。
4. 摘要:灰色小字,1 到 2 行截断。
5. 底部一行:来源(前面有小圆点或来源图标,例如金十数据、BlockBeats、PANews)、蓝色的 # 标签(如 #ETH #ETF),最右边是情绪标签(利好绿色、利空红色、中性灰色)。

交互:点击条目进入快讯详情;下拉刷新;上拉加载;列表顶部若有新快讯出现,显示"有 N 条新快讯,点击查看"的悬浮提示(补充,是否用实时推送或定时轮询,与后端确认)。切换分类时保持各自的滚动位置与数据缓存更佳。

### 5.9 快讯详情页(设计稿有)

顶部导航:左边返回;右边分享图标和收藏(书签)图标。

内容区从上到下:
1. 标签行:级别标签、# 标签、情绪标签。
2. 标题,粗体。
3. 来源与发布时间一行,下面一条分隔线。
4. 正文:支持多段落文本;如果后端返回富文本,需要安全渲染。
5. "相关币种"卡片:币种图标、交易对(如 ETH/USDT)、最新价、涨跌幅(按涨跌上色)。可能有多个币种。
6. "相关点位"卡片(浅蓝底):标题"相关点位",右侧"查看"链接;下面一行是交易对加方向标签,右侧是"入场区间 3,480 - 3,520";再下面一行是 TP1、TP2、SL 数值(SL 红色)。点击"查看"进入点位详情。如果这条快讯没有关联点位,整个卡片不显示。未解锁用户看到的关联点位内容规则同点位列表的锁定规则(见 5.11)。

底部固定两个按钮:分享、收藏,两个各占一半。收藏后按钮高亮并变为"已收藏",再点一次取消。分享调用系统分享或复制链接,内容由后端提供分享文案与链接,没有则用标题加应用下载页兜底(待确认)。

### 5.10 点位列表页(设计稿有)

顶部标题"交易点位"加一个蓝色小标签"实时策略";右上角一个锁形按钮"全部解锁",点击弹出"解锁全部点位"弹窗;若用户已解锁,该按钮隐藏或改为"已解锁"状态显示。

筛选胶囊:全部、做多、做空、自选。"自选"就是用户收藏的点位,与"我的收藏"里的点位是同一份数据。

点位卡片(白底圆角):
1. 头部:币种图标 + 交易对(如 BTC/USDT)+ 方向标签(做多绿底、做空红底);右侧状态标签:"运行中"为绿色描边样式,"已失效"为灰色。
2. 中部三行(数字使用等宽字体):入场区间(如 67,000 - 67,500);止盈(TP1 69,000  TP2 71,000  TP3 73,500,数量不固定,可能只有 1 到 3 个);止损(红色数字)。
3. 底部小字:左侧"发布时间 2026-07-13 20:30",右侧"有效期 24H"。

"已失效"的卡片整体降低透明度,内部文字变灰。点击卡片进入点位详情。

## 6. 数据模型(前端视角的字段约定)

以下是页面需要用到的数据字段,用于设计 Mock 与前端内部模型。后端接口的实际字段名以后端文档为准,不一致时只在接口层做字段映射,页面始终使用前端内部模型。

快讯:编号;级别(紧急、要闻、普通);标题;摘要;正文;来源名称与来源图标;标签列表;情绪(利好、利空、中性);发布时间;分类;缩略图(可选);相关币种列表(交易对、最新价、涨跌幅);关联点位(可选,含点位编号与摘要信息);当前用户是否已收藏。

点位:编号;交易对;币种图标;方向(做多、做空);状态(运行中、已失效,可能还有其他终态,以后端为准);入场区间下限与上限;止盈列表(名称如 TP1、价格、仓位比例);止损价;当前价格(实时数据);发布时间;有效期(小时);策略说明;是否被锁定;当前用户是否已收藏。

多空比:币种;多方占比;空方占比;比值;各交易所比值列表(交易所名称、比值)。

行情条目:交易对;最新价;24 小时涨跌幅。

用户:编号;昵称;邮箱或手机号;头像;钱包地址(可选);是否已开启 2FA;是否已解锁点位;通知开关四项。

消息:编号;类型;标题;摘要;时间;是否已读;跳转目标(类型加编号)。

## 7. 接口对接层设计要求

### 7.1 总体思路

页面不直接调用 uni.request,也不直接使用后端字段。所有网络请求走 api 层的模块方法,方法返回前端内部模型。每个 api 方法同时有 Mock 实现与真实实现,由一个环境开关(如是否启用 Mock)决定用哪一个,签名、参数、返回结构完全一致。后端接口就绪后,逐模块把开关切到真实,页面不需要改。

### 7.2 请求封装

统一封装一个 request 工具,负责:基础地址(区分开发、测试、生产环境配置)、自动附带登录凭证、统一超时、统一响应结构解析(默认假设为"状态码 + 提示信息 + 数据"的结构,具体格式以后端文档为准,只改解析处即可)、统一错误处理(业务错误提示、网络错误提示、登录失效跳转登录页)、分页参数的统一处理(页码或游标方式以后端为准)。

### 7.3 接口模块清单(前端期望,仅供与后端对齐,路径与字段不要写死)

1. 认证:注册、账号登录、钱包登录(取随机串、提交签名)、第三方登录、发送验证码、找回密码、重置密码。
2. 用户与安全:个人资料读取与修改、修改密码、2FA 获取绑定信息与校验、通知设置读取与保存。
3. 首页与行情:首页精选数据、多空比、实时行情、全局搜索。
4. 快讯:分类、列表、详情、收藏与取消收藏、关联点位。
5. 点位:列表(带筛选)、详情、自选(收藏)、解锁状态查询、NFT 校验解锁、历史点位。
6. NFT 与链上:钱包持仓查询、购买链接获取、获取说明内容。
7. 收藏:收藏的快讯列表、收藏的点位列表。
8. 客服与静态内容:客服联系方式、风险提示、关于我们、服务协议与隐私条款。
9. 消息推送:设备令牌注册、消息列表、标记已读。

上述模块对应后端约 42 个接口,前端在对接阶段按后端提供的文档逐个核对参数与返回值。如果发现页面需要的字段后端没有提供,记录成"接口缺口清单"反馈给后端团队,不要在前端自行编造。

### 7.4 实时数据

首页行情与点位详情的"当前价格"需要实时刷新。前端封装一个统一的行情服务:优先使用后端提供的 WebSocket,如果后端只提供普通接口,则用 5 到 10 秒的轮询;页面不可见或离开时必须停止订阅或轮询,回到前台再恢复。行情数据一律经由后端获取,前端不直接调用任何交易所或链上服务。方案待与后端确认。

### 7.5 推送

前端负责申请系统通知权限、获取设备推送令牌、登录后上报给后端、并处理"点击推送通知跳转"——推送内容里带类型和编号,点击后直达对应的快讯详情或点位详情。具体推送通道(如 uni-push 或客户指定的服务)待确认。

## 8. Mock 数据要求

1. Mock 数据要覆盖设计稿里出现的全部内容:快讯示例(如 SEC 推迟以太坊现货 ETF 决定、贝莱德比特币 ETF 持仓、币安新杠杆交易对、Polygon AggLayer v2)、点位示例(BTC 做多运行中、ETH 做空运行中、SOL 做多已失效)、多空比、四个行情条目、客服渠道、通知设置。
2. 除了正常数据,还要能模拟:空列表、加载缓慢、请求失败、未登录、点位被锁定与已解锁、快讯无关联点位、收藏与取消收藏后的状态变化、分页到底。
3. Mock 层做成可随时开关,并保证与真实接口层的调用方式一致。



## 10. 验收标准

1. 页面还原度:对照 code.html,布局、层级、颜色、圆角、图标风格一致;字号按第 3 节放大后清晰可读。
2. 功能完整:18 个页面或弹窗(加补充的消息列表页)全部可访问,入口与跳转关系正确。
3. 状态完整:每个列表页与详情页具备加载、空、错误、下拉刷新、上拉加载状态;点位具备"运行中、已失效、已锁定、已解锁"的展示;收藏状态在列表、详情、我的收藏之间保持一致。
4. 接口对接就绪:Mock 与真实接口可一键切换;页面里没有出现后端原始字段或硬编码的接口地址、客服账号、NFT 链接。
5. 适配:iOS 与 Android 主流机型、刘海屏与安全区、浅色与深色主题均无明显错位。
6. 质量:无控制台报错;组件复用合理;文案全部在语言包中;涨跌配色统一由 Token 控制。
7. 联调完成度:后端提供接口的模块,前端已联通并通过主流程测试;后端未就绪的模块,保留 Mock 并在交付说明里列明。

## 12. 给 AI 开发助手的硬性约束

1. 不要编造接口路径、字段名或业务规则;不确定就按本文档默认方案实现并保持可配置,同时在代码注释或说明里标出。
